长篇真正会崩的地方

单章质量靠提示词，长篇质量靠状态管理。

只用聊天窗口续写

  • 上下文塞满后开始遗忘早期设定
  • 人物称谓、立场、已知信息前后矛盾
  • 伏笔埋了没人记，最后收不回来
  • 同一个桥段反复用，读者先察觉
  • 改一章，后面几十章的引用全错

这个工作台的做法

  • 每章生成摘要，历史按需压缩而不是硬塞
  • 关键事实抽取 + 设定库比对，冲突先拦下
  • 伏笔台账区分“规划 / 已埋 / 已回收”
  • 修改前提示受影响的后续段落
  • 章节状态机：未确认不进入上下文

写作流程

跟着工作台的提示走，就不会乱。

STEP 05

三步跑起来

Windows 本地运行，浏览器访问。程序目录同时是数据目录。

  1. 放程序：下载 Release 里的 show-me-the-story.exe，放进一个空目录。
  2. 填 Key：把仓库里的 config.example.json 复制为 api.json，把占位符换成你自己的 Key。
  3. 启动：双击 exe，浏览器打开 http://localhost:48090。
{
  "api_key": "请在这里填入你的 API Key",
  "base_url": "https://api.deepseek.com",
  "model": "deepseek-chat",
  "fallback_model": "deepseek-chat",
  "max_tokens": 32768,
  "http_timeout_seconds": 600,
  "context_budget_tokens": 300000
}

换用其他 OpenAI 兼容服务时，同时修改 base_url 与 model 即可。 详细步骤与每个界面的说明见 使用手册。

安全提示：api.json 保存的是明文密钥，不要提交到 Git，也不要随目录打包外发。 程序默认监听所有网卡且无鉴权，只想自己使用时请以管理员身份运行「仅本机访问」脚本，或关闭服务。
